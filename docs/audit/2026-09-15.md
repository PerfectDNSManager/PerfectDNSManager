# Revue du 15 septembre 2026

Périmètre : application Android, configuration de compilation et de publication, transports DNS, préférences et imports, partage, ADB embarqué, backend principal et source legacy, dépendances résolues, retours GitHub. La revue combine lecture des chemins sensibles, inspection structurelle des écrans et ressources, lint, tests et consultation des avis OSV. Elle ne constitue pas une garantie d’absence de vulnérabilité ni une validation sur chaque appareil.

## Corrections de cette passe

- **IPv6, issue #3** : quand le blocage est désactivé, autoriser explicitement AF_INET6. Sans adresse/route IPv6, Android bloquait cette famille par défaut. Quand le blocage est activé, conserver sa capture par `::/0`.
- **Routage local** : remplacer l’adresse privée du tunnel en `/24` par une adresse de documentation en `/32`, pour éviter le chevauchement avec un LAN `192.168.50.0/24`.
- **Presse-papiers, issue #1** : supprimer la copie automatique lors de la création d’un partage. La copie exige un bouton explicite ; marquer le contenu sensible lorsque la plateforme le permet. Aucune lecture automatique du presse-papiers ni permission de lecture dédiée trouvée.
- **NextDNS DoQ** : l’ancien chemin `/ID` n’était jamais envoyé au serveur QUIC. Placer l’ID dans le nom d’hôte, migrer les anciennes adresses connues, refuser les chemins/paramètres DoQ non interprétés, valider la saisie d’ID.
- **Profils** : valider aussi secondaire, IPv6 et longueur des noms ; vérifier les modifications ; conserver une modification de preset comme personnalisation ; relire les fiches fournisseur après modification ; tolérer les anciennes préférences invalides sans planter le catalogue.
- **Export** : respecter « sans réglages » pour les domaines de test et exclusions, inclure les options DNS classique/variantes manquantes.
- **Moniteur DoT** : ne pas conclure à une panne DNS sur réseau déconnecté ; restaurer le nom surveillé pour un arrêt demandé après recréation du processus.
- **DoH** : exiger la réussite de la protection des sockets avant connexion.
- **Tests DNS** : retirer `myip.opendns.com` des IP de résolveurs, car il renvoie l’IP du client ; retirer le repli Google étiqueté FAI quand le DNS opérateur est inconnu.
- **ADB** : borner connexion et lecture du pairing, valider les six chiffres, borner la sortie shell, ne plus sérialiser les payloads ADB dans les messages de journal ; protéger la libération d’un contexte natif non initialisé.
- **TLS** : rejeter explicitement l’authentification client sur le gestionnaire dédié aux serveurs ; ne pas ignorer une erreur de lecture EKU.
- **Métadonnées distantes** : borner plusieurs lectures texte avant décodage et allocation supplémentaire.
- **BouncyCastle** : mise à jour de 1.78.1 vers 1.84. OSV signalait quatre avis sur les anciennes dépendances ; aucun sur les trois modules 1.84 interrogés. Leur présence antérieure ne prouve pas l’exploitation des fonctions concernées dans PDM.
- **APK release** : corriger le nom de classe Ookla protégé contre le renommage R8.
- **Backend** : redirections de partage sans lecture R2 préalable, taille de token bornée, page de téléchargement de secours si GitHub échoue. Porter lecture bornée, limiteurs fermés sur panne et création conditionnelle anti-collision vers le source legacy.
- **Maintenance** : formats numériques avec locale explicite, pluriels manquants, texte de licence Apache référencé par NOTICE.

## Dépendances et bibliothèques natives

84 coordonnées Maven du runtime ont été interrogées auprès d’OSV. Quatre avis initiaux BouncyCastle : GHSA-4cx2-fc23-5wg6, GHSA-wg6q-6289-32hp, GHSA-574f-3g2m-x479 et GHSA-c3fc-8qff-9hwx. `npm audit` backend : zéro avis connu au moment de la revue.

Le dépôt contient ces binaires, pas leur chaîne complète de reconstruction C/C++ : cette vérification n’est pas un audit intégral de leur implémentation. ## Lecture des avertissements

Les 325 avertissements initiaux ne sont pas 325 failles : ils incluent textes construits dynamiquement, choix graphiques, alternatives de layout TV, versions suggérées, icônes et conseils de style Gradle. Les alertes de sécurité ont été examinées séparément. Le gestionnaire TLS sans validation de CA dans ADB participe au protocole de pairing local SPAKE2 et n’est pas utilisé pour les résolveurs publics. Les implémentations « trust all » présentes dans certaines dépendances ne prouvent pas leur utilisation par PDM : le chemin DoQ actif impose `TlsTrust.forHost`.

Le HTTP clair reste autorisé pour les serveurs Ookla dynamiques. Les transports DNS sensibles exigent HTTPS/TLS/QUIC et refusent les redirections TLS vers HTTP. Il n’est pas justifié de casser Ookla ou de masquer globalement lint pour afficher artificiellement zéro avertissement.

## Limites et essais encore requis

- Pas d’émulateur disponible ni de TV/Fire TV physique attachée : permission VPN, navigation télécommande, boot, réseau IPv6 réel, pairing ADB et changement de réseau restent à vérifier sur appareil.
- Le ticket Formuler #2 reste ouvert et non reproduit.
- Le test de fuite DNS reste une observation indirecte d’un résolveur et peut subir les caches ; aucune promesse de preuve exhaustive d’absence de fuite.
- Mot de passe de partage à six caractères conservé selon le choix utilisateur historique ; l’expiration ne supprime pas le risque de recherche hors ligne sur un blob déjà copié.
- Les correctifs sont livrés sur le canal bêta. La production stable et le déploiement legacy ne sont pas promus automatiquement.
- Les résultats OSV/npm et le scan de motifs de secrets ne couvrent pas toutes les classes de vulnérabilités. Aucun motif de clé privée/token détecté dans le scan du contenu suivi courant ; les copies externes de l’ancien historique ne peuvent pas être garanties supprimées.
